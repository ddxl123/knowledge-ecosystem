# knowledge-ecosystem 核心概念层级升级任务

## 你的任务
对指定目录下的所有 .md 文件进行「核心概念层级升级」。

## 工作目录
`/Users/linlong/.openclaw/workspace/knowledge-ecosystem`

## 需要处理的文件类型

### A类：原子知识文件（需要升级核心概念层级）
路径模式：除 INDEX.md、BOOK-INFO.md、00-INDEX.md 之外的所有 .md 文件

### B类：BOOK-INFO.md（需要增强说明内容）
路径模式：各书目目录下的 BOOK-INFO.md

### C类：INDEX.md（需要增强说明内容）
路径模式：各领域目录下的 INDEX.md

## 处理规则

### 规则1：内容忠于原文件
- 核心概念的结构必须对应文件实际所属的领域/书目内容
- 不可添加与该文件主题无关的内容
- 例如：红宝书的单元结构是因为书本身就是按 unit 组织的，保持这个结构
- 例如：化学反应原理按反应速率/化学平衡/电化学等概念组织，保持这个结构

### 规则2：不罗列纯知识（不列出单个闪卡/单个词汇）
- **禁止**直接罗列单个知识点、单个词汇、单个公式等
- **允许**举示例（代表性例子，3-5个即可）
- 错误示例：
  ```
  ## Unit 1
  abandon, ability, abnormal, ...
  ```
- 正确示例：
  ```
  ## Unit 1
  红宝书第一单元的单词，涵盖基础高频词汇。
  示例：abandon（放弃）、ability（能力）、abnormal（异常的）
  ```

### 规则3：所有原子文件都要升级层级
- 在现有内容外层添加「核心概念」层级
- 不仅是词汇表文件，所有类型的原子文件都需要
- 升级后的结构应包含：
  - 该文件/章节的核心概念描述（是什么、为什么重要）
  - 知识点的组织结构（按什么维度分类）
  - 代表性示例（而非穷举）

### 规则4：说明类文件只增强不拆解
- BOOK-INFO.md：保持说明性质，补充书目信息（如适用人群、学习建议、与其他书目的对比等）
- INDEX.md：保持索引性质，补充分类说明、使用建议等
- 不要把说明类文件原子化

### 规则5：深度收集
- 对每个核心概念条目，需要收集完整的信息
- 不是简单的标题罗列，而是要有实质性的描述
- 每个概念条目应包含：概念名称、概念描述、与其他概念的关系、代表性示例
- 对于教辅类文件，应参考该教辅的实际内容体系

### 规则6：Markdown格式统一
- 使用标准 Markdown 标题层级（# ## ### ####）
- 列表使用 - 或 1. 格式
- 表格使用 | 格式（仅在需要对比时使用）
- 代码块使用 ``` 格式
- 数学公式使用 LaTeX 格式（$...$ 或 $$...$$）

## 工作流程
1. 读取指定目录下的所有 .md 文件
2. 根据文件类型（A/B/C）应用对应规则
3. 对每个文件进行升级/增强
4. 将升级后的内容写回原文件（覆盖）
5. 完成后输出处理报告（处理了多少文件、跳过了多少文件）

## 输出要求
- 直接覆盖原文件
- 处理完每个文件后打印进度（如：[1/100] 处理完成：xxx.md）
- 最终输出汇总报告
