# knowledge-ecosystem 核心概念层级升级任务 V2

## 核心概念的本质
核心概念是给未来 AI 的提示词（prompt），用于指导深度收集具体知识内容（如闪卡内容集合）。
核心概念不是知识本身，而是"蓝图"——告诉 AI：
1. 这个条目是什么（仅限本文件/本目录，不跨文件不跨目录）
2. 知识结构有哪些（本文件内有哪些子主题/子分类）
3. 需要收集哪些原子知识点（只罗列"要收集什么"，不进行实际收集）

## 处理范围
指定目录下的所有 .md 文件。

## 文件分类处理规则

### A类：原子知识文件
路径模式：除 INDEX.md、BOOK-INFO.md、00-INDEX.md 之外的所有 .md 文件

**处理方式：**
在文件顶部添加 `## 核心概念` 层级，内容包含：

```markdown
## 核心概念

### 条目描述
[用1-3句话说明这个文件是什么，仅限本文件内容，不涉及其他文件]

### 知识结构
[列出本文件内的子主题/子分类结构，用树形或列表形式]

### 待收集原子知识点
[列出本文件需要收集的原子知识点清单，只罗列"要收集什么"，不实际收集]
- 原子知识点1：[简要描述]
- 原子知识点2：[简要描述]
- ...
```

**严格禁止：**
- 禁止跨文件、跨目录引用（如：不要在Unit14中提及Unit1-13或其他书目）
- 禁止罗列具体知识内容（如具体单词、具体公式、具体定义）
- 禁止给出示例
- 禁止写"代表性示例"
- 禁止写模板化的概述（如"生活技能领域的实用知识模块"这种废话）

### B类：BOOK-INFO.md
路径模式：各书目目录下的 BOOK-INFO.md

**处理方式：**
增强说明内容，包含：
- 基本信息（书名、作者、年份、适用考试）
- 内容结构（本书包含哪些模块/章节）
- 适用人群（具体到考试类型/学习阶段，不要写"备考相关考试的考生"这种废话）
- 学习建议（针对本书特点的具体建议）
- 与其他书目的区别（如有）

### C类：INDEX.md
路径模式：各领域目录下的 INDEX.md

**处理方式：**
INDEX 就是 INDEX，保持索引性质，只做整理优化：
- 清理冗余内容
- 确保目录结构清晰
- 不添加知识性内容
- 不添加"使用建议"等多余板块

## 工作流程
1. 用 find 列出所有文件
2. 逐个读取，判断类型（A/B/C）
3. 按规则处理
4. 写回原文件（覆盖）
5. 输出汇总报告
