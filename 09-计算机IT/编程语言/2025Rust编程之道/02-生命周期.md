# 生命周期

## 生命周期基础
- 生命周期：引用保持有效的范围，大部分情况编译器可自动推导（生命周期省略规则）
- 标注语法：`'a` 表示生命周期参数，`&'a i32` 表示具有生命周期'a的引用
- 函数标注：`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str` 返回值的生命周期等于x和y中较短的
- 生命周期不改变引用的实际存活时间，只是帮助编译器理解引用间的关系
- 结构体中的引用：`struct Excerpt<'a> { part: &'a str }` 存储引用的结构体必须标注生命周期
- 'static生命周期：整个程序运行期间有效，字符串字面量具有'static生命周期

## 生命周期省略规则
- 规则一：每个引用参数各自获得一个生命周期参数
- 规则二：只有一个输入生命周期参数时，该生命周期赋给所有输出引用
- 规则三：方法中&self的生命周期赋给所有输出引用
- 如果三条规则后仍无法确定所有引用的生命周期，编译器报错需手动标注
- 大多数函数不需要手动标注，编译器能自动推导

## 结构体与生命周期
- 包含引用的结构体必须标注生命周期：`struct Parser<'input> { text: &'input str }`
- 结构体实例的生命周期不能超过其引用数据的生命周期
- impl块中的生命周期：`impl<'a> Excerpt<'a> { fn method(&self) -> &'a str {...} }`
- 方法返回引用时，生命周期需与结构体或参数关联
- 避免结构体存储引用：优先使用拥有所有权的类型（如String而非&str）

## 高级生命周期
- 生命周期子类型：`'a: 'b` 表示'a至少和'b活得一样长
- 生命周期型变：协变（子类型可替代父类型）和逆变（函数参数）
- trait对象的生命周期：`Box<dyn Trait + 'a>`、`&'a (dyn Trait + 'a)`
- HRTB（Higher-Ranked Trait Bounds）：`for<'a> Fn(&'a str) -> &'a str`
- 闭包中的生命周期：编译器通常能推导，复杂情况需手动标注

## 生命周期最佳实践
- 优先使用拥有所有权的类型，减少引用的复杂性
- 尽量让编译器自动推导，只在必要时手动标注
- 理解'static：不要为了"修复"生命周期错误而随意使用'static
- 使用Cow<'a, T>：读多写少场景，按需克隆
- 设计API时考虑调用者的便利性，避免过度复杂的生命周期约束
- 当生命周期过于复杂时，考虑重构设计（如使用Rc/Arc、克隆数据等）
