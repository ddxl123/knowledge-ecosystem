# 错误处理

## Result与Option
- Result<T, E>：可恢复错误，Ok(T)表示成功，Err(E)表示失败
- Option<T>：可能不存在的值，Some(T)表示有值，None表示无值
- unwrap()：取出值，失败时panic，仅用于原型或确定不会失败的场景
- expect("msg")：类似unwrap但可自定义panic信息
- 组合器：map()、and_then()、or_else()、unwrap_or()、unwrap_or_else()
- ?运算符：`let value = some_operation()?;` 错误时自动返回Err，正确时取出Ok值

## 自定义错误类型
- 实现Display和Error trait：`impl fmt::Display for MyError { fn fmt(...) }`
- 错误枚举：`enum AppError { IoError(io::Error), ParseError(num::ParseIntError), Custom(String) }`
- 实现From trait：`impl From<io::Error> for AppError` 支持?运算符自动转换
- thiserror库：`#[derive(thiserror::Error)]` 自动实现Error trait
  ```rust
  #[derive(thiserror::Error, Debug)]
  enum MyError {
      #[error("IO error: {0}")]
      Io(#[from] std::io::Error),
  }
  ```
- anyhow库：`anyhow::Result<T>` 提供动态错误类型，适合应用程序
- 错误上下文：`anyhow::Context` trait 的`.context("msg")` 添加上下文信息

## panic与不可恢复错误
- panic!宏：程序遇到不可恢复错误时终止执行
- 默认行为：展开栈（清理资源）或中止进程（通过Cargo.toml配置）
- RUST_BACKTRACE=1：环境变量设置后panic时打印完整调用栈
- catch_unwind：`std::panic::catch_unwind(|| { ... })` 捕获panic（不推荐滥用）
- 何时panic：代码逻辑错误、违反不变量、不可能到达的代码
- 何时Result：预期可能发生的错误、外部输入错误、IO操作失败

## 错误传播模式
- ?运算符链式调用：`file.read_to_string(&mut content)?; let data: Data = serde_json::from_str(&content)?;`
- 函数返回类型：`fn process() -> Result<Data, AppError> { ... }`
- main函数返回Result：`fn main() -> Result<(), Box<dyn Error>> { ... }`
- map_err：转换错误类型，`io_result.map_err(AppError::Io)`
- and_then：链式操作，每步都可能失败
- 错误处理策略：传播（?）、转换（map_err）、忽略（unwrap_or）、记录并继续

## 错误处理最佳实践
- 库代码：使用具体的自定义错误类型，不要用anyhow
- 应用代码：可以使用anyhow简化错误处理
- 不要过度unwrap：对可能失败的操作使用Result和?
- 错误信息要有意义：包含足够的上下文帮助调试
- 区分可恢复和不可恢复错误：IO失败→Result，数组越界→panic
- 使用thiserror减少样板代码，使用anyhow简化应用错误处理
- 错误文档：在函数文档中说明可能返回的错误类型
