# 异常处理

## 异常机制基础
- try-catch块：`try { 可能抛出异常的代码 } catch(异常类型 e) { 处理代码 }`
- throw语句：`throw std::runtime_error("error message");`
- catch(...)：捕获所有类型的异常
- 异常传播：异常沿调用栈向上传播，直到被匹配的catch捕获
- 未捕获异常：调用std::terminate()，默认终止程序
- 异常规范（C++11）：`noexcept` 指定函数不抛出异常，编译器可优化

## 标准异常类
- exception基类：`<stdexcept>` 头文件
- logic_error：逻辑错误——invalid_argument、domain_error、length_error、out_of_range
- runtime_error：运行时错误——range_error、overflow_error、underflow_error
- what()方法：返回错误描述字符串
- 自定义异常：继承std::exception，重写what()方法
- 嵌套异常（C++11）：`std::nested_exception`、`std::throw_with_nested()`

## 异常安全
- 基本保证：异常发生后对象处于有效状态，无资源泄漏
- 强保证：异常发生后状态回滚到操作之前（事务语义）
- 不抛出保证：操作保证不抛出异常（noexcept）
- RAII模式：利用构造/析构函数自动管理资源，确保异常安全
- 智能指针：unique_ptr、shared_ptr自动释放内存
- lock_guard：自动管理互斥锁的获取和释放
- 异常安全的资源管理：先分配新资源，再释放旧资源

## 异常处理最佳实践
- 按引用捕获：`catch(const std::exception& e)` 避免对象切片
- 异常层次：从具体到一般排列catch块
- 不在析构函数中抛出异常：析构函数默认noexcept
- 不在异常处理中分配可能失败的资源
- 使用RAII替代手动try-catch管理资源
- noexcept用于移动构造/赋值和swap函数
- 异常不应用于正常控制流，只用于异常情况
- 考虑使用std::optional、std::expected（C++23）作为异常替代

## 错误处理替代方案
- 错误码：函数返回int表示错误，C风格，简单但容易忽略
- std::optional（C++17）：`std::optional<int>` 表示可能有值也可能无值
- std::expected（C++23）：`std::expected<T, E>` 要么成功值要么错误值
- assert断言：`assert(condition)` 调试期检查，release模式下被移除
- static_assert（C++11）：编译期断言，`static_assert(sizeof(int) == 4, "...")`
- std::variant（C++17）：类型安全的联合体，可表示多种类型之一
