# 模块化

## 模块化发展历程
- 无模块时代：全局变量、IIFE（立即执行函数），容易命名冲突和依赖混乱
- CommonJS：Node.js采用，require()导入、module.exports导出，同步加载
- AMD（Asynchronous Module Definition）：require.js实现，异步加载，适合浏览器
- CMD（Common Module Definition）：sea.js实现，按需加载
- UMD（Universal Module Definition）：兼容CommonJS和AMD的通用方案
- ES Module：ES6标准，import/export，编译时静态分析，浏览器和Node.js通用

## ES Module语法
- 导出：`export const name = 'value'`、`export default function() {}`
- 导入：`import { name } from './module.js'`、`import defaultName from './module.js'`
- 重命名：`export { name as myName }`、`import { name as myName }`
- 全部导入：`import * as module from './module.js'`
- 动态导入：`import('./module.js').then(m => {})` 返回Promise
- 导入即执行：`import './sideEffect.js'` 仅执行模块副作用
- export必须在模块顶层，不能在条件语句或函数内

## CommonJS模块
- 导出：`module.exports = { }` 或 `exports.name = value`
- 导入：`const module = require('./module')`
- 特点：运行时加载、同步执行、值的拷贝（非引用）
- 模块缓存：require后缓存结果，再次require返回同一对象
- __dirname：当前模块目录、__filename：当前模块文件路径
- 动态require：可以在条件语句和函数内使用require()
- Node.js中CommonJS与ESM共存：.cjs为CommonJS，.mjs为ESM

## 模块打包工具
- Webpack：模块打包器，将所有模块打包为少量bundle文件
- Vite：基于ESM的开发服务器，开发环境无需打包，极速热更新
- Rollup：适合库开发，Tree-shaking效果好，输出更干净的代码
- esbuild：Go语言编写，速度极快的打包和压缩工具
- Parcel：零配置打包工具，自动安装依赖
- Tree-shaking：静态分析import/export，删除未使用的代码（ESM优势）

## 模块化最佳实践
- 一个文件一个模块，职责单一
- 优先使用ES Module，兼容性需求用CommonJS
- 避免循环依赖：A依赖B、B又依赖A会导致加载异常
- 按需导入：`import { specific } from 'library'` 而非全部导入
- 代码分割：动态import()实现按需加载，减少初始包体积
- 第三方库：使用package.json的exports字段定义模块入口
- 区分开发依赖和生产依赖：devDependencies vs dependencies
