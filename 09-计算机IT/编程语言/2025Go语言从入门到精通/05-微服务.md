# 微服务

## 微服务架构概念
- 微服务：将单体应用拆分为一组小型、自治的服务，每个服务独立部署
- 单体 vs 微服务：单体简单但难以扩展，微服务灵活但增加复杂性
- 核心原则：单一职责、自治、去中心化治理、独立部署、容错设计
- 通信方式：同步（HTTP/gRPC）、异步（消息队列）
- API网关：统一入口，负责路由、认证、限流、负载均衡

## gRPC服务
- gRPC：Google的高性能RPC框架，基于HTTP/2和Protocol Buffers
- .proto文件：定义服务接口和消息格式
  ```protobuf
  service UserService {
    rpc GetUser(GetUserRequest) returns (User);
  }
  ```
- 四种通信模式：一元RPC、服务端流、客户端流、双向流
- Go实现：`protoc --go_out=. --go-grpc_out=. user.proto` 生成代码
- 拦截器（Interceptor）：一元拦截器和流拦截器，实现日志、认证等
- 错误处理：`status.Error(codes.NotFound, "user not found")`
- 超时与取消：通过context传递deadline和取消信号

## 服务发现与注册
- 服务注册：服务启动时将地址注册到注册中心
- 服务发现：客户端或网关从注册中心获取可用服务地址
- Consul：HashiCorp的服务发现和配置工具，支持健康检查
- etcd：CoreOS的分布式键值存储，Kubernetes使用
- Nacos：阿里巴巴的服务发现和配置管理平台
- 健康检查：定期检测服务是否可用，自动摘除不健康实例
- 负载均衡：轮询、加权轮询、最少连接、一致性哈希

## 消息队列
- 异步通信：解耦服务，削峰填谷，提高系统弹性
- Kafka：高吞吐分布式消息系统，适合日志收集和流处理
- RabbitMQ：功能丰富的AMQP消息代理，支持多种消息模式
- NATS：轻量级高性能消息系统，适合云原生场景
- Go客户端：sarama(Kafka)、amqp091-go(RabbitMQ)、nats.go(NATS)
- 消息模式：点对点（Queue）、发布订阅（Topic/Subscription）、请求回复
- 消息确认：确保消息不丢失，消费者处理完成后确认

## 云原生与部署
- Docker容器化：Dockerfile定义镜像，多阶段构建减小镜像体积
- Dockerfile最佳实践：基础镜像选择、层缓存优化、最小化镜像
- Kubernetes（K8s）：容器编排，Deployment、Service、ConfigMap、Secret
- Helm：K8s的包管理器，Chart定义一组相关资源
- 可观测性：日志（结构化日志）、指标（Prometheus+Grafana）、链路追踪（Jaeger/Zipkin）
- 配置管理：环境变量、配置文件、配置中心（Consul/Nacos/Viper）
- 限流熔断：golang.org/x/time/rate限流、Hystrix/Resilience4j熔断模式
