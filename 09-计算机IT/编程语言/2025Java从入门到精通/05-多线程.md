# 多线程

## 线程基础
- 创建线程方式：继承Thread类、实现Runnable接口、实现Callable接口（有返回值）
- 线程生命周期：NEW → RUNNABLE → (BLOCKED / WAITING / TIMED_WAITING) → TERMINATED
- 常用方法：`start()`启动、`run()`执行体、`sleep()`休眠、`join()`等待、`yield()`让出CPU
- 守护线程：`setDaemon(true)`，JVM退出时自动终止，如GC线程
- 线程优先级：1-10，默认5，`setPriority()`设置，不保证执行顺序

## 线程同步
- synchronized关键字：同步方法（锁this）、同步代码块（锁指定对象）
- 死锁条件：互斥、持有并等待、不可剥夺、循环等待，至少两把锁交叉获取
- volatile关键字：保证可见性（每次读从主内存）、禁止指令重排序
- 原子类：AtomicInteger、AtomicLong、AtomicReference等，基于CAS实现无锁操作
- ThreadLocal：线程局部变量，每个线程独立副本，常用于数据库连接和用户会话

## 锁机制
- ReentrantLock：可重入锁，比synchronized更灵活，支持公平锁、可中断锁
- Condition条件变量：配合ReentrantLock使用，`await()`等待、`signal()`唤醒
- ReadWriteLock读写锁：读操作共享、写操作独占，适合读多写少场景
- StampedLock（Java 8+）：乐观读+悲观读写，性能优于ReadWriteLock
- CountDownLatch：倒计数器，等待N个线程完成后再继续
- CyclicBarrier：循环栅栏，所有线程到达后一起继续

## 线程池
- ThreadPoolExecutor：核心参数——corePoolSize、maximumPoolSize、keepAliveTime、workQueue、handler
- 拒绝策略：AbortPolicy（抛异常）、CallerRunsPolicy（调用者执行）、DiscardPolicy（丢弃）、DiscardOldestPolicy（丢弃最旧）
- Executors工厂类：newFixedThreadPool（固定大小）、newCachedThreadPool（缓存）、newSingleThreadExecutor（单线程）、newScheduledThreadPool（定时）
- submit() vs execute()：submit返回Future可获取结果，execute无返回值
- 最佳实践：避免使用Executors创建无界队列线程池，手动创建ThreadPoolExecutor

## 虚拟线程（Java 21）
- 虚拟线程：轻量级线程，由JVM调度而非操作系统，可创建数百万个
- 创建方式：`Thread.ofVirtual().start(task)`、`Executors.newVirtualThreadPerTaskExecutor()`
- 优势：高并发场景下大幅降低内存占用和上下文切换开销
- 注意事项：虚拟线程中避免使用synchronized（会pinning），改用ReentrantLock
- 适用场景：IO密集型任务（网络请求、数据库查询），不适合CPU密集型
