# 协程

## 协程基础
- 协程：轻量级线程，由Kotlin编译器和运行时管理，而非操作系统
- 启动协程：`launch { }`（不返回结果）、`async { }`（返回Deferred结果）
- CoroutineScope：协程的作用域，管理协程的生命周期
- suspend函数：用`suspend`关键字标记，只能在协程或其他suspend函数中调用
- 结构化并发：子协程与父协程关联，父协程等待所有子协程完成
- 协程比线程轻量：可创建数万个协程，切换成本低

## 协程构建器
- launch：启动协程返回Job，不返回结果，适合"发射并忘记"
- async：启动协程返回Deferred<T>，通过.await()获取结果
- runBlocking：桥接阻塞和非阻塞世界，阻塞当前线程直到协程完成
- coroutineScope：创建新的协程作用域，挂起直到所有子协程完成
- supervisorScope：子协程失败不影响其他子协程
- GlobalScope：全局作用域，生命周期与应用相同（不推荐滥用）

## 调度器
- Dispatchers.Default：CPU密集型任务，线程数=CPU核心数
- Dispatchers.IO：IO密集型任务，共享线程池，适合网络/文件操作
- Dispatchers.Main：Android主线程，用于UI操作
- Dispatchers.Unconfined：不限制线程，在当前线程启动，挂起后在恢复的线程执行
- 切换调度器：`withContext(Dispatchers.IO) { 在IO线程执行 }`
- 自定义调度器：`newSingleThreadContext("MyThread")` 创建专用线程

## 异常处理
- launch的异常：自动传播给父协程，可通过CoroutineExceptionHandler捕获
- async的异常：异常被封装在Deferred中，调用.await()时抛出
- try-catch：在协程中正常使用try-catch捕获异常
- CoroutineExceptionHandler：仅在根协程（launch）上有效
- SupervisorJob：子协程异常不影响兄弟协程
- 取消协程：`job.cancel()` 取消协程，协程需检查isActive或调用yield()

## Flow
- Flow<T>：冷流（Cold Stream），collect时才开始发射数据
- 创建：`flow { emit(value) }`，emit发射值，emitAll发射另一个流
- 操作符：map、filter、transform、take、drop、zip、combine、flatMapConcat/mergeLatest
- 终端操作符：collect、toList、toSet、first、single、reduce、fold
- StateFlow：热流，始终有当前值，类似LiveData，用于UI状态管理
- SharedFlow：热流，可配置缓存和重放策略
- buffer：`flow.buffer()` 在单独协程中收集，提升性能
- conflate：`flow.conflate()` 跳过中间值，只处理最新值
