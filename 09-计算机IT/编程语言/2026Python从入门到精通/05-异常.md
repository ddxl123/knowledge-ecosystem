# 异常处理

## 异常机制基础
- try-except：`try: 可能出错的代码 except ErrorType as e: 处理`
- 多个except：分别捕获不同类型的异常
- 通用except：`except Exception as e:` 捕获所有非系统退出异常（不推荐裸except）
- try-except-else：没有异常时执行else块
- try-except-finally：无论是否异常都执行finally块（清理资源）
- 异常对象：e.args异常参数、str(e)错误信息、type(e)异常类型

## 常见异常类型
- ValueError：值错误，如int('abc')
- TypeError：类型错误，如1 + 'a'
- KeyError：字典键不存在
- IndexError：列表索引越界
- AttributeError：对象属性不存在
- FileNotFoundError：文件不存在
- ZeroDivisionError：除以零
- ImportError/ModuleNotFoundError：导入模块失败
- IOError/OSError：IO和操作系统错误
- RuntimeError：运行时错误

## 抛出与自定义异常
- raise语句：`raise ValueError("invalid input")` 抛出异常
- 重新抛出：`except: raise` 捕获后重新抛出（不改变异常）
- 自定义异常：继承Exception类
  ```python
  class MyError(Exception):
      def __init__(self, message, code):
          super().__init__(message)
          self.code = code
  ```
- 异常链：`raise NewError("msg") from original_error` 保留原始异常
- assert断言：`assert x > 0, "x must be positive"` 开发阶段检查条件

## 异常处理最佳实践
- 精确捕获：捕获具体的异常类型，而非Exception
- 不要忽略异常：至少记录日志，不要空的except块
- EAFP原则：Python风格是"先做再说"（Easier to Ask Forgiveness than Permission）
- try块尽量小：只包裹可能出错的代码
- 资源清理用with：`with open('file') as f:` 自动关闭
- 向上传播：不处理的异常应该让调用者知道
- 自定义异常层次：为项目定义有意义的异常类

## 上下文管理器
- with语句：自动管理资源的获取和释放
- 自定义上下文管理器：实现__enter__和__exit__方法
  ```python
  class Timer:
      def __enter__(self):
          self.start = time.time()
          return self
      def __exit__(self, *args):
          self.elapsed = time.time() - self.start
  ```
- contextlib模块：@contextmanager装饰器简化创建
  ```python
  @contextmanager
  def timer():
      start = time.time()
      yield
      print(f"Elapsed: {time.time() - start}")
  ```
- suppress：`with suppress(FileNotFoundError):` 忽略指定异常
