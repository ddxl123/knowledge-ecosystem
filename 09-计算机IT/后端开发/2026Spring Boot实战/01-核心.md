## 核心知识点

### 一、Spring Boot 4.x 架构演进

Spring Boot 4.x（2026年）在 3.x 基础上进一步优化性能和开发体验。

- **核心变化：**
  - 最低要求 Java 21+，全面拥抱虚拟线程
  - 基于 Spring Framework 7.x
  - 原生支持 Jakarta EE 11
  - 改进的 GraalVM 原生镜像支持，启动时间 < 100ms
  - 内置可观测性（Observability）增强

- **项目初始化：**
  ```bash
  # 使用 Spring Initializr CLI
  spring init --dependencies=web,data-jpa,security \
    --java-version=21 --type=gradle-project my-app
  ```

### 二、虚拟线程集成

```java
// application.yml 启用虚拟线程
server:
  tomcat:
    virtual-threads:
      enabled: true

// 或编程方式配置
@Configuration
public class VirtualThreadConfig {
    @Bean
    public TomcatProtocolHandlerCustomizer<?> protocolHandlerVirtualThreadCustomizer() {
        return protocolHandler -> {
            protocolHandler.setExecutor(Executors.newVirtualThreadPerTaskExecutor());
        };
    }
}
```

- **虚拟线程优势：**
  - 轻量级线程，创建成本极低（约 1KB vs 平台线程 1MB）
  - 适合 I/O 密集型任务，无需异步编程
  - 可创建数百万虚拟线程而不会 OOM
  - 与传统阻塞代码完全兼容

- **注意事项：**
  - 不适合 CPU 密集型计算
  - `synchronized` 块会 pin 虚拟线程，改用 `ReentrantLock`
  - ThreadLocal 使用需谨慎，考虑 ScopedValue

### 三、GraalVM 原生镜像

```java
// 原生编译提示
@RegisterReflectionForBinding({User.class, Order.class})
@RestController
public class UserController { }

// 构建原生镜像
// Gradle: ./gradlew nativeCompile
// Maven: ./mvnw -Pnative native:compile

// 运行原生可执行文件
./build/native/nativeCompile/my-app  # 启动 < 100ms
```

- **原生镜像注意事项：**
  - 反射需要通过 `@RegisterReflectionForBinding` 声明
  - 动态代理需配置 `RuntimeHints`
  - 资源文件需通过 `@RegisterResourceForReflection` 注册
  - 延迟初始化可能影响首次请求延迟

### 四、响应式 WebFlux

```java
// 响应式 Controller
@RestController
@RequestMapping("/api/users")
public class UserReactiveController {
    
    @Autowired
    private ReactiveUserRepository userRepository;
    
    @GetMapping
    public Flux<UserDTO> list() {
        return userRepository.findAll()
            .map(UserDTO::fromEntity);
    }
    
    @GetMapping("/{id}")
    public Mono<ResponseEntity<UserDTO>> getById(@PathVariable Long id) {
        return userRepository.findById(id)
            .map(user -> ResponseEntity.ok(UserDTO.fromEntity(user)))
            .defaultIfEmpty(ResponseEntity.notFound().build());
    }
    
    @PostMapping
    public Mono<ResponseEntity<UserDTO>> create(@Valid @RequestBody UserCreateRequest request) {
        return userRepository.save(User.fromRequest(request))
            .map(user -> ResponseEntity.status(201).body(UserDTO.fromEntity(user)));
    }
}

// 响应式 Repository
public interface ReactiveUserRepository extends ReactiveCrudRepository<User, Long> {
    Mono<User> findByUsername(String username);
    Flux<User> findByStatus(String status);
}
```

- **WebFlux vs Web MVC：**
  - WebFlux：非阻塞 I/O，少量线程处理高并发
  - Web MVC：阻塞 I/O + 虚拟线程（2026 推荐方案）
  - 选择建议：新项目优先考虑 MVC + 虚拟线程

### 五、2026年新特性

- **改进的自动配置：**
  - 更智能的条件评估
  - 配置属性支持 record 类型
  - 配置文件分组（Config Data Import）

- **可观测性增强：**
  ```java
  // Micrometer + OpenTelemetry 集成
  @Observed(name = "user.find", contextualName = "find-user")
  public UserDTO findById(Long id) {
      return userRepository.findById(id).map(UserDTO::fromEntity).orElseThrow();
  }
  ```

- **HTTP 接口客户端：**
  ```java
  @HttpExchange(url = "/api/users", accept = "application/json")
  public interface UserClient {
      @GetExchange("/{id}")
      Mono<UserDTO> getById(@PathVariable Long id);
      
      @PostExchange
      Mono<UserDTO> create(@RequestBody UserCreateRequest request);
  }
  ```

- **改进的测试支持：** `@MockitoBean` 替代 `@MockBean`，更好的 AOT 测试
