## 核心知识点

### 一、备份策略

- **按类型分：**
  - 全量备份：备份整个数据库，恢复简单但耗时
  - 增量备份：只备份上次备份后的变化，节省空间
  - 差异备份：备份上次全量备份后的所有变化

- **按方式分：**
  - 逻辑备份：导出 SQL 语句（mysqldump），可跨版本恢复
  - 物理备份：复制数据文件（xtrabackup），速度快

- **备份策略建议：**
  - 小型数据库（< 50GB）：每天全量 mysqldump
  - 中型数据库：每周全量 + 每天增量
  - 大型数据库：xtrabackup 全量 + binlog 增量

### 二、mysqldump 逻辑备份

```bash
# 备份单个数据库
mysqldump -u root -p --single-transaction mydb > mydb_backup.sql

# 备份多个数据库
mysqldump -u root -p --databases db1 db2 > multi_db_backup.sql

# 备份所有数据库
mysqldump -u root -p --all-databases --single-transaction > all_backup.sql

# 只备份表结构
mysqldump -u root -p --no-data mydb > schema_only.sql

# 只备份数据
mysqldump -u root -p --no-create-info mydb > data_only.sql

# 带压缩备份
mysqldump -u root -p --single-transaction mydb | gzip > mydb_backup.sql.gz

# 恢复
mysql -u root -p mydb < mydb_backup.sql
gunzip < mydb_backup.sql.gz | mysql -u root -p mydb
```

- **关键参数：**
  - `--single-transaction`：InnoDB 一致性备份（不锁表）
  - `--routines`：包含存储过程和函数
  - `--triggers`：包含触发器（默认开启）
  - `--events`：包含事件
  - `--master-data=2`：记录 binlog 位置（注释形式）

### 三、Percona XtraBackup 物理备份

```bash
# 全量备份
xtrabackup --backup --target-dir=/backup/full \
    --user=root --password=xxx

# 准备备份（应用 redo log）
xtrabackup --prepare --target-dir=/backup/full

# 恢复
systemctl stop mysql
rm -rf /var/lib/mysql/*
xtrabackup --copy-back --target-dir=/backup/full
chown -R mysql:mysql /var/lib/mysql
systemctl start mysql

# 增量备份
xtrabackup --backup --target-dir=/backup/inc1 \
    --incremental-basedir=/backup/full

# 增量恢复
xtrabackup --prepare --apply-log-only --target-dir=/backup/full
xtrabackup --prepare --apply-log-only --target-dir=/backup/full \
    --incremental-dir=/backup/inc1
xtrabackup --prepare --target-dir=/backup/full
```

### 四、binlog 管理与恢复

```sql
-- 查看 binlog 状态
SHOW VARIABLES LIKE 'log_bin';
SHOW BINARY LOGS;
SHOW MASTER STATUS;

-- 查看 binlog 内容
mysqlbinlog --base64-output=decode-rows -v binlog.000001

-- 基于 binlog 的时间点恢复
mysqlbinlog --start-datetime="2024-01-01 00:00:00" \
    --stop-datetime="2024-01-01 12:00:00" \
    binlog.000001 | mysql -u root -p

-- 基于位置恢复
mysqlbinlog --start-position=154 --stop-position=1024 \
    binlog.000001 | mysql -u root -p

-- binlog 清理
SET GLOBAL expire_logs_days = 7;  -- 保留7天
PURGE BINARY LOGS BEFORE '2024-01-01 00:00:00';
```

### 五、备份自动化与验证

```bash
#!/bin/bash
# 自动备份脚本
BACKUP_DIR="/backup/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="mydb"

# 创建备份
mysqldump -u root -p"$MYSQL_PWD" --single-transaction \
    --routines --triggers --events "$DB_NAME" | \
    gzip > "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# 删除7天前的备份
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete

# 验证备份完整性
gunzip -t "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz" && \
    echo "备份验证成功" || echo "备份文件损坏"
```

- **备份最佳实践：**
  - 定期执行备份恢复演练
  - 备份文件异地存储（至少一份在不同物理位置）
  - 监控备份任务执行状态
  - 记录备份元数据（时间、大小、binlog 位置）
  - 生产环境备份前评估对性能的影响
