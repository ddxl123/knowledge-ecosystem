## 核心知识点

### 一、事务基本概念

```sql
-- 显式事务
START TRANSACTION;  -- 或 BEGIN
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;  -- 提交

-- 出错时回滚
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
-- 发生错误
ROLLBACK;  -- 回滚所有操作

-- 保存点
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
SAVEPOINT sp1;
UPDATE accounts SET balance = balance - 200 WHERE id = 2;
ROLLBACK TO sp1;  -- 只回滚到保存点
COMMIT;
```

### 二、ACID 特性

- **原子性（Atomicity）：** 事务中的操作要么全部成功，要么全部回滚，不存在中间状态。通过 undo log 实现。
- **一致性（Consistency）：** 事务前后数据库从一个一致状态转换到另一个一致状态。如转账前后总金额不变。
- **隔离性（Isolation）：** 多个并发事务之间互不干扰。通过锁和 MVCC 实现。
- **持久性（Durability）：** 事务提交后数据永久保存。通过 redo log 实现（WAL 机制）。

### 三、事务隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| READ UNCOMMITTED | ✅ | ✅ | ✅ |
| READ COMMITTED | ❌ | ✅ | ✅ |
| REPEATABLE READ（默认） | ❌ | ❌ | ❌* |
| SERIALIZABLE | ❌ | ❌ | ❌ |

```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;

-- 设置隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

- **脏读：** 读到其他事务未提交的数据
- **不可重复读：** 同一事务内两次读取同一行数据结果不同（被其他事务修改）
- **幻读：** 同一事务内两次查询返回不同数量的行（被其他事务插入）
- **InnoDB 在 REPEATABLE READ 下通过 MVCC + 间隙锁基本解决了幻读问题**

### 四、MVCC 机制

- **多版本并发控制（MVCC）：**
  - 每行数据有隐藏列：`DB_TRX_ID`（最后修改事务ID）、`DB_ROLL_PTR`（回滚指针）
  - 通过 undo log 构建数据的历史版本链
  - 读操作不加锁，通过 Read View 判断可见性

- **Read View：**
  - `m_ids`：创建时活跃的事务ID列表
  - `min_trx_id`：活跃事务最小ID
  - `max_trx_id`：下一个将分配的事务ID
  - `creator_trx_id`：创建该 Read View 的事务ID

- **可见性判断规则：**
  1. `DB_TRX_ID == creator_trx_id`：自己修改的，可见
  2. `DB_TRX_ID < min_trx_id`：修改在 Read View 前提交，可见
  3. `DB_TRX_ID >= max_trx_id`：修改在 Read View 后开始，不可见
  4. `min_trx_id <= DB_TRX_ID < max_trx_id`：检查是否在 `m_ids` 中，不在则可见

- **RC vs RR 的区别：**
  - RC：每次 SELECT 都生成新的 Read View
  - RR：整个事务只在第一次 SELECT 时生成 Read View

### 五、长事务与死锁处理

```sql
-- 查看当前事务
SELECT * FROM information_schema.INNODB_TRX;

-- 查看死锁日志
SHOW ENGINE INNODB STATUS;

-- 杀掉阻塞事务
KILL <thread_id>;
```

- **避免长事务：**
  - 设置 `innodb_lock_wait_timeout`（默认50秒）
  - 将大事务拆分为小事务
  - 避免在事务中执行耗时操作（如调用外部 API）

- **死锁处理：**
  - InnoDB 自动检测死锁，回滚代价较小的事务
  - 按固定顺序访问表和行
  - 减少事务持有锁的时间
  - 使用合理的索引减少锁范围
