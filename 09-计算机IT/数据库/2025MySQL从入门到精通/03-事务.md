# 事务管理

## 核心知识点

### 一、事务基础

#### 1. 什么是事务
- 一组不可分割的数据库操作序列
- 要么全部成功，要么全部失败
- 保证数据的一致性和完整性

#### 2. ACID特性
| 特性 | 说明 |
|------|------|
| 原子性（Atomicity） | 事务是不可分割的工作单位 |
| 一致性（Consistency） | 事务前后数据保持一致 |
| 隔离性（Isolation） | 并发事务之间互不干扰 |
| 持久性（Durability） | 事务提交后永久保存 |

### 二、事务操作

#### 1. 基本语法
```sql
-- 开启事务
START TRANSACTION;
-- 或
BEGIN;

-- 执行SQL
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 提交事务
COMMIT;

-- 回滚事务
ROLLBACK;
```

#### 2. 保存点
```sql
START TRANSACTION;

INSERT INTO orders (user_id, amount) VALUES (1, 100);
SAVEPOINT sp1;

INSERT INTO order_items (order_id, product_id) VALUES (1, 1);
-- 出错回滚到保存点
ROLLBACK TO sp1;

COMMIT;
```

### 三、隔离级别

#### 1. 四种隔离级别
| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| READ UNCOMMITTED | ✓ | ✓ | ✓ |
| READ COMMITTED | ✗ | ✓ | ✓ |
| REPEATABLE READ | ✗ | ✗ | ✗* |
| SERIALIZABLE | ✗ | ✗ | ✗ |

*MySQL的REPEATABLE READ通过MVCC+间隙锁解决了大部分幻读问题

#### 2. 设置隔离级别
```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;

-- 设置隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

### 四、MVCC机制

#### 1. 什么是MVCC
- 多版本并发控制（Multi-Version Concurrency Control）
- 通过维护数据的多个版本实现并发控制
- 读操作不加锁，提高并发性能

#### 2. 实现原理
- **隐藏字段** — trx_id（事务ID）、roll_pointer（回滚指针）
- **undo log** — 存储数据的旧版本
- **Read View** — 事务开始时创建的快照

#### 3. 可见性判断
```
如果记录的trx_id < min_trx_id → 可见
如果记录的trx_id > max_trx_id → 不可见
如果min_trx_id <= trx_id <= max_trx_id：
    如果在m_ids中 → 不可见（事务未提交）
    如果不在m_ids中 → 可见（事务已提交）
```

### 五、事务最佳实践
1. 事务尽量短小，避免长事务
2. 避免在事务中进行远程调用
3. 合理选择隔离级别
4. 使用保存点处理部分回滚
5. 注意死锁检测和处理
