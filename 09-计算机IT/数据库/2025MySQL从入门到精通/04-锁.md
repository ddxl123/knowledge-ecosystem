# 锁机制

## 核心知识点

### 一、锁概述

#### 1. 为什么需要锁
- 保证数据一致性
- 控制并发访问
- 防止数据竞争

#### 2. 锁的分类
```
按粒度分：
- 表锁（Table Lock）
- 行锁（Row Lock）
- 页锁（Page Lock）

按类型分：
- 共享锁（S Lock / 读锁）
- 排他锁（X Lock / 写锁）
- 意向锁（IS / IX）
```

### 二、表锁

#### 1. 表锁操作
```sql
-- 加锁
LOCK TABLES users READ;    -- 读锁
LOCK TABLES users WRITE;   -- 写锁

-- 解锁
UNLOCK TABLES;
```

#### 2. 特点
- 粒度大，并发度低
- 开销小，加锁快
- 适合读多写少场景
- MyISAM默认使用表锁

### 三、行锁

#### 1. 行锁类型
| 类型 | 说明 | 触发条件 |
|------|------|---------|
| 记录锁（Record Lock） | 锁定单条记录 | 等值查询命中唯一索引 |
| 间隙锁（Gap Lock） | 锁定索引间隙 | 范围查询，防止幻读 |
| 临键锁（Next-Key Lock） | 记录锁+间隙锁 | 默认行锁类型 |

#### 2. 行锁演示
```sql
-- 事务A
BEGIN;
SELECT * FROM users WHERE id = 1 FOR UPDATE; -- 加排他锁

-- 事务B（阻塞）
UPDATE users SET name = 'bob' WHERE id = 1; -- 等待锁释放

-- 事务A
COMMIT; -- 释放锁，事务B继续执行
```

#### 3. 行锁特点
- 粒度小，并发度高
- 开销大，加锁慢
- 适合高并发场景
- InnoDB默认使用行锁

### 四、意向锁

#### 1. 作用
- 表明事务意图在表中加行锁
- 快速判断表中是否有行锁
- 避免逐行检查

#### 2. 类型
- **IS锁（意向共享锁）** — 事务打算加行级共享锁
- **IX锁（意向排他锁）** — 事务打算加行级排他锁

### 五、死锁

#### 1. 什么是死锁
```
事务A：锁定行1，等待锁定行2
事务B：锁定行2，等待锁定行1
→ 互相等待，形成死锁
```

#### 2. 死锁检测
```sql
-- 查看死锁信息
SHOW ENGINE INNODB STATUS;

-- 查看锁等待
SELECT * FROM information_schema.INNODB_LOCK_WAITS;
```

#### 3. 死锁处理
- **超时机制** — 等待超过阈值自动回滚
- **死锁检测** — InnoDB自动检测并回滚代价小的事务
- **等待图** — 构建事务等待关系图，检测环路

#### 4. 避免死锁
1. 按固定顺序访问资源
2. 减少事务持有锁的时间
3. 使用较低的隔离级别
4. 合理设计索引，减少锁范围
5. 避免长事务

### 六、乐观锁与悲观锁

#### 1. 悲观锁
```sql
-- SELECT ... FOR UPDATE
BEGIN;
SELECT * FROM products WHERE id = 1 FOR UPDATE;
UPDATE products SET stock = stock - 1 WHERE id = 1;
COMMIT;
```

#### 2. 乐观锁
```sql
-- 使用版本号
SELECT id, stock, version FROM products WHERE id = 1;
-- 应用层处理
UPDATE products SET stock = stock - 1, version = version + 1 
WHERE id = 1 AND version = 5;
-- 检查affected rows，如果为0则重试
```
