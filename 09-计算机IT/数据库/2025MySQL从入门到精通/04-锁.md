## 核心知识点

### 一、锁的分类体系

- **按粒度分：**
  - 全局锁：锁定整个数据库实例
  - 表级锁：锁定整张表
  - 行级锁：锁定单行或多行

- **按类型分：**
  - 共享锁（S Lock / 读锁）：多个事务可同时持有
  - 排他锁（X Lock / 写锁）：独占，阻塞其他读写
  - 意向锁（IS/IX）：表级锁，表示事务打算在表中加行级锁

### 二、全局锁与表锁

```sql
-- 全局锁（全库只读，用于全库备份）
FLUSH TABLES WITH READ LOCK;
UNLOCK TABLES;

-- 表锁
LOCK TABLES users READ;      -- 读锁
LOCK TABLES users WRITE;     -- 写锁
UNLOCK TABLES;

-- 元数据锁（MDL，自动加锁）
-- DML 操作自动加 MDL 读锁
-- DDL 操作自动加 MDL 写锁
-- 问题：长事务持有 MDL 读锁，DDL 被阻塞，后续查询全部阻塞

-- 查看 MDL 锁
SELECT * FROM performance_schema.metadata_locks;
```

### 三、行锁机制

```sql
-- 记录锁（Record Lock）：锁定索引记录
SELECT * FROM users WHERE id = 1 FOR UPDATE;  -- 加排他锁
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;  -- 加共享锁

-- 行锁是加在索引上的！
-- 没有索引时，行锁退化为表锁
```

- **行锁加锁规则：**
  - `SELECT ... LOCK IN SHARE MODE`：加共享锁
  - `SELECT ... FOR UPDATE`：加排他锁
  - `INSERT`：加插入意向锁
  - `UPDATE`：加排他锁
  - `DELETE`：加排他锁

- **行锁的条件：**
  - 必须走索引，否则退化为表锁
  - 等值查询唯一索引：只锁单行
  - 范围查询：锁住整个范围

### 四、间隙锁与临键锁

```sql
-- 间隙锁（Gap Lock）：锁定索引记录之间的间隙
-- 防止其他事务在间隙中插入新记录（解决幻读）
-- 示例：表中有 id = 1, 5, 10
SELECT * FROM users WHERE id BETWEEN 3 AND 7 FOR UPDATE;
-- 锁定间隙：(1, 5) 和 (5, 10)

-- 临键锁（Next-Key Lock）：记录锁 + 间隙锁
-- InnoDB 在 RR 隔离级别下默认使用临键锁
-- 锁定范围：(左开右闭]
-- 示例：id = 5 的临键锁锁定 (1, 5]
```

- **加锁规则总结（RR 隔离级别）：**
  - 唯一索引等值查询：命中 → 记录锁；未命中 → 间隙锁
  - 非唯一索引等值查询：命中 → 临键锁 + 间隙锁
  - 范围查询：临键锁
  - 无索引：全表扫描，所有行加锁

### 五、死锁分析与预防

```sql
-- 查看死锁信息
SHOW ENGINE INNODB STATUS;

-- 设置锁等待超时
SET innodb_lock_wait_timeout = 10;  -- 默认50秒

-- 开启死锁检测（默认开启）
SET innodb_deadlock_detect = ON;
```

- **死锁产生的条件：**
  - 互斥条件：资源被独占
  - 请求与保持：持有资源的同时请求新资源
  - 不可剥夺：已获取的资源不能被强制释放
  - 循环等待：事务间形成环形等待

- **死锁案例：**
  ```sql
  -- 事务A
  BEGIN;
  UPDATE accounts SET balance = 100 WHERE id = 1;  -- 锁 id=1
  UPDATE accounts SET balance = 200 WHERE id = 2;  -- 等待 id=2
  
  -- 事务B
  BEGIN;
  UPDATE accounts SET balance = 300 WHERE id = 2;  -- 锁 id=2
  UPDATE accounts SET balance = 400 WHERE id = 1;  -- 等待 id=1 → 死锁
  ```

- **预防策略：**
  - 按固定顺序访问行（如按 id 从小到大）
  - 减小事务粒度，缩短事务执行时间
  - 使用合理的索引，避免锁升级
  - 业务允许的情况下使用较低隔离级别
