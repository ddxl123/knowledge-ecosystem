## 核心知识点

### 一、索引基础概念

- **索引是什么：** 特殊的数据结构，用于加速数据检索，类似书的目录
- **索引的优点：**
  - 大幅减少磁盘 I/O 次数
  - 加速 SELECT 查询
  - 加速表连接（JOIN）
  - 加速排序和分组
- **索引的代价：**
  - 占用额外存储空间
  - 降低 INSERT/UPDATE/DELETE 速度（需维护索引）
  - 过多索引会增加优化器选择时间

### 二、B+Tree 索引结构

- **B+Tree 特点：**
  - 非叶子节点只存储键值，不存储数据
  - 叶子节点存储完整数据，并通过链表相连
  - 树高通常 2-4 层，亿级数据仅需 3-4 次磁盘 I/O
  - 所有查询都到达叶子节点，查询性能稳定

- **InnoDB 索引模型：**
  - 聚簇索引（主键索引）：叶子节点存储完整行数据
  - 二级索引（辅助索引）：叶子节点存储主键值
  - 通过二级索引查询需要"回表"（先查主键，再查数据）

### 三、索引类型

```sql
-- 主键索引（自动创建）
ALTER TABLE users ADD PRIMARY KEY (id);

-- 唯一索引
ALTER TABLE users ADD UNIQUE INDEX idx_email (email);

-- 普通索引
ALTER TABLE users ADD INDEX idx_username (username);

-- 联合索引（最左前缀原则）
ALTER TABLE users ADD INDEX idx_status_created (status, created_at);

-- 全文索引
ALTER TABLE articles ADD FULLTEXT INDEX ft_content (title, content);
SELECT * FROM articles WHERE MATCH(title, content) AGAINST('MySQL 优化' IN BOOLEAN MODE);

-- 前缀索引
ALTER TABLE users ADD INDEX idx_email_prefix (email(10));

-- 覆盖索引（查询字段都在索引中，无需回表）
-- 索引：INDEX idx_status_created (status, created_at)
SELECT status, created_at FROM users WHERE status = 'active';
```

### 四、索引设计原则

- **选择性高的列优先：** 区分度大的列放前面（如 user_id > status）
- **最左前缀原则：** 联合索引 `(a, b, c)` 支持 `a`、`a,b`、`a,b,c` 查询
- **覆盖索引：** 将查询字段加入索引，避免回表
- **索引下推（ICP）：** MySQL 5.6+ 在索引层面过滤数据，减少回表次数

```sql
-- 索引设计示例
-- 查询：SELECT * FROM orders WHERE user_id = ? AND status = 'paid' ORDER BY created_at DESC
-- 最佳索引：
ALTER TABLE orders ADD INDEX idx_user_status_created (user_id, status, created_at);

-- 覆盖索引示例
-- 查询：SELECT id, username, email FROM users WHERE username = ?
-- 索引：INDEX idx_username_email (username, email)  -- 包含所有查询字段
```

### 五、索引失效场景与 EXPLAIN

```sql
-- EXPLAIN 分析查询
EXPLAIN SELECT * FROM users WHERE status = 'active';

-- EXPLAIN 关键字段：
-- type: 访问类型（ALL < index < range < ref < eq_ref < const < system）
-- key: 实际使用的索引
-- rows: 预估扫描行数
-- Extra: Using index(覆盖索引), Using filesort(额外排序), Using temporary(临时表)
```

- **索引失效的常见场景：**
  - 对索引列使用函数：`WHERE YEAR(created_at) = 2024` → 改为范围查询
  - 隐式类型转换：`WHERE phone = 13800138000`（phone 是 VARCHAR）
  - 使用 `OR` 连接非索引列：`WHERE indexed_col = 1 OR non_indexed = 2`
  - `LIKE '%keyword'`：左模糊导致索引失效
  - `NOT IN`、`!=`、`<>`：可能导致全表扫描
  - 联合索引不满足最左前缀
  - 数据量小时优化器选择全表扫描
