## 核心知识点

### 一、SQL 查询优化

```sql
-- 1. 避免 SELECT *
SELECT id, username, email FROM users WHERE status = 'active';

-- 2. 使用 EXPLAIN 分析
EXPLAIN SELECT * FROM orders WHERE user_id = 1 AND status = 'paid';
-- 关注：type(避免ALL)、key(是否用索引)、rows(扫描行数)

-- 3. 避免索引失效
-- 错误：WHERE YEAR(created_at) = 2024
-- 正确：WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01'

-- 4. 小表驱动大表
-- IN 适合子查询结果集小的情况
SELECT * FROM orders WHERE user_id IN (SELECT id FROM users WHERE status = 'active');
-- EXISTS 适合外表结果集小的情况
SELECT * FROM users u WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- 5. 批量操作替代循环
-- 错误：逐条 INSERT
INSERT INTO logs (msg) VALUES ('a');
INSERT INTO logs (msg) VALUES ('b');
-- 正确：批量 INSERT
INSERT INTO logs (msg) VALUES ('a'), ('b'), ('c');

-- 6. LIMIT 优化（深分页问题）
-- 慢：SELECT * FROM orders ORDER BY id LIMIT 1000000, 10
-- 快：SELECT * FROM orders WHERE id > 1000000 ORDER BY id LIMIT 10
-- 或使用延迟关联：
SELECT * FROM orders o
INNER JOIN (SELECT id FROM orders ORDER BY id LIMIT 1000000, 10) t ON o.id = t.id;
```

### 二、Schema 优化

- **数据类型选择：**
  - 整数：优先 `TINYINT`/`SMALLINT`/`MEDIUMINT`，避免不必要的 `BIGINT`
  - 字符串：定长用 `CHAR`，变长用 `VARCHAR`，大文本用 `TEXT`
  - 时间：`TIMESTAMP`（4字节，1970-2038）vs `DATETIME`（8字节，更宽范围）
  - 金额：用 `DECIMAL(10,2)`，不用 `FLOAT`/`DOUBLE`

- **范式与反范式：**
  - 范式化：减少数据冗余，更新简单，但查询需 JOIN
  - 反范式化：增加冗余字段，查询快，但更新复杂
  - 实践：核心表范式化，查询密集表适度反范式化

- **分表策略：**
  - 垂直分表：将大字段拆到扩展表（如 user 表和 user_profile 表）
  - 水平分表：按规则将数据分散到多张表

### 三、InnoDB 参数调优

```sql
-- 缓冲池大小（最重要的参数，建议物理内存的 60-80%）
SET GLOBAL innodb_buffer_pool_size = 4294967296;  -- 4GB

-- 缓冲池实例数（减少并发竞争）
SET GLOBAL innodb_buffer_pool_instances = 8;

-- redo log 大小
SET GLOBAL innodb_log_file_size = 1073741824;  -- 1GB

-- 刷盘策略
-- 0: 每秒刷盘（可能丢1秒数据）
-- 1: 每次事务提交都刷盘（最安全，默认）
-- 2: 每次提交写入OS缓存，每秒刷盘
SET GLOBAL innodb_flush_log_at_trx_commit = 1;
SET GLOBAL sync_binlog = 1;  -- binlog 同步策略

-- 并发线程数
SET GLOBAL innodb_thread_concurrency = 0;  -- 0表示不限制

-- IO 容量
SET GLOBAL innodb_io_capacity = 2000;  -- SSD 建议 2000-4000
SET GLOBAL innodb_io_capacity_max = 4000;
```

### 四、慢查询分析

```sql
-- 开启慢查询日志
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;  -- 超过1秒记录
SET GLOBAL log_queries_not_using_indexes = ON;

-- 分析慢查询日志
-- mysqldumpslow -s t -t 10 /var/log/mysql/slow.log

-- 使用 performance_schema
SELECT * FROM performance_schema.events_statements_summary_by_digest
ORDER BY SUM_TIMER_WAIT DESC LIMIT 10;

-- 查看正在执行的查询
SHOW PROCESSLIST;
```

### 五、读写分离与分库分表

- **读写分离：**
  - 主库（Master）处理写操作
  - 从库（Slave）处理读操作
  - 通过 MySQL 复制（Replication）同步数据
  - 应用层路由或中间件（MyCat、ProxySQL、ShardingSphere）

- **分库分表：**
  - 垂直分库：按业务模块拆分（用户库、订单库、商品库）
  - 水平分库：同一业务数据按规则分散到多个库
  - 分片键选择：选择查询频率高的字段（如 user_id）
  - 常用中间件：ShardingSphere、Vitess

- **分库分表带来的问题：**
  - 分布式事务
  - 跨库 JOIN
  - 全局 ID 生成（雪花算法、UUID）
  - 数据迁移与扩容
