# 状态管理

## 状态管理概述
- 何时需要全局状态管理：多个不相关组件共享状态、深层嵌套组件需要数据
- 本地状态 vs 全局状态：useState适合组件内，全局状态库适合跨组件共享
- 状态管理原则：最小化全局状态、保持状态扁平、派生状态不存Store

## Context API
- React内置方案，适合低频更新的全局数据（主题、语言、用户认证）
- 创建：`const ThemeContext = React.createContext('light')`
- Provider：`<ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>`
- 消费：`const theme = useContext(ThemeContext)`
- Context问题：值变化时所有消费者都会重渲染，不适合高频更新
- 优化：拆分Context（Value Context + Dispatch Context）、使用memo
- 适用场景：主题切换、语言切换、当前用户信息

## Redux
- Redux：最经典的状态管理库，单一数据源、纯函数reducer、不可变状态
- 三大原则：单一Store、State只读（通过action）、纯函数reducer
- Store：`const store = createStore(rootReducer)`
- Action：`{ type: 'INCREMENT', payload: 1 }` 描述发生了什么
- Reducer：`(state, action) => newState` 纯函数计算新状态
- Redux Toolkit（RTK）：官方推荐工具包，简化Redux使用
  ```js
  const counterSlice = createSlice({
    name: 'counter', initialState: { value: 0 },
    reducers: { increment: state => { state.value += 1 } }
  });
  ```
- configureStore：`configureStore({ reducer: { counter: counterReducer } })`
- useSelector：`const count = useSelector(state => state.counter.value)` 读取状态
- useDispatch：`const dispatch = useDispatch(); dispatch(increment())` 触发action
- RTK Query：数据获取和缓存解决方案

## Zustand
- Zustand：轻量级状态管理，API简洁，无Provider
- 创建Store：`const useStore = create(set => ({ count: 0, increment: () => set(s => ({ count: s.count + 1 })) }))`
- 使用：`const { count, increment } = useStore()`
- 选择器：`const count = useStore(state => state.count)` 精确订阅
- 中间件：persist（持久化）、devtools（Redux DevTools）、immer（可变语法）
- 优势：无Provider包裹、无reducer样板代码、TypeScript友好

## 其他方案
- Jotai：原子化状态管理，类似Recoil但更轻量
- Recoil：Facebook推出，Atom和Selector概念，已被React Compiler趋势替代
- MobX：响应式状态管理，可变状态+自动追踪依赖
- React Query/TanStack Query：服务端状态管理，缓存、自动刷新、乐观更新
- SWR：Vercel的数据获取策略库，stale-while-revalidate模式
- 选择建议：小项目用Context/Zustand、大项目用Redux Toolkit、服务端状态用React Query
